# Wings Bucha: запуск адмінки з PostgreSQL

## Що вже підготовлено

Сайт зроблений на React + Vite + TanStack Start. Адмінка доступна за адресою `/admin`.

Дані підготовлені для PostgreSQL через Prisma:

- будинки і типи будинків;
- заявки з контактної форми;
- контакти сайту;
- документи сайту;
- хід будівництва;
- відео для другого анімованого блоку;
- фото, PDF і відео з адмінки через upload у папку `public/uploads` або іншу папку сервера.

Якщо `DATABASE_URL` не заданий, сайт працює в демо-режимі з локальними даними. Для бойового запуску треба підключити PostgreSQL.

## 1. Що має зробити замовник на сервері

Створити окрему порожню PostgreSQL-базу, наприклад:

```text
wingsbucha_db
```

Після цього дати розробнику або DevOps не прямий доступ до всієї бази, а тільки connection string до цієї порожньої бази:

```text
postgresql://USER:PASSWORD@HOST:5432/wingsbucha_db?schema=public
```

Цей рядок треба зберігати тільки в env-змінних сервера, не в коді і не в GitHub.

## 2. Env-змінні

На сервері треба задати:

```bash
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/wingsbucha_db?schema=public"
ADMIN_PASSWORD="надійний-пароль-для-адмінки"
ADMIN_SESSION_SECRET="довгий-випадковий-секрет-для-cookie"
UPLOAD_DIR="public/uploads"
PUBLIC_UPLOAD_BASE_URL="/uploads"
```

`UPLOAD_DIR` можна змінити на іншу абсолютну папку сервера, якщо хостинг так вимагає.

`ADMIN_PASSWORD` обов'язковий для продакшену. Локально, якщо він не заданий, працює демо-пароль `admin`.

## 3. Встановлення

```bash
npm install
npm run build
```

Під час `npm run build`, якщо `DATABASE_URL` заданий, автоматично виконається:

```bash
prisma migrate deploy
```

Це створить таблиці у порожній базі. Якщо `DATABASE_URL` не заданий, міграції пропускаються, і збірка не падає.

## 4. Ручні команди для бази

Якщо треба окремо перевірити міграції:

```bash
npm run db:migrate
```

Для локальної розробки з локальним PostgreSQL:

```bash
npm run db:push
npm run db:studio
```

## 5. Як замовнику працювати з адмінкою

1. Відкрити `/admin`.
2. Увійти з паролем із `ADMIN_PASSWORD`.
3. У вкладці `Об'єкти` додавати або редагувати будинки.
4. Додавати нові типи: таунхаус, дуплекс, котедж або будь-який інший.
5. Обрати валюту ціни: USD або UAH.
6. Завантажити фото кнопкою `Обрати фото` або перетягнути файл у поле.
7. У плануваннях ставити статус: `Вільно`, `Резерв` або `Продано`.
8. Натиснути `Зберегти`.
9. У вкладці `Документи` додавати PDF або фото документів.
10. У вкладці `Хід будівництва` додавати етапи, дати, відсоток готовності та фото.
11. У вкладці `Медіа` завантажити відео для другого анімованого блоку або залишити поточне фото.
12. У вкладці `Заявки` переглядати заявки з форми.
13. У вкладці `Контакти` міняти телефон, email, месенджери та адресу.

## 6. Що важливо перед продакшеном

Адмінка захищена паролем через `ADMIN_PASSWORD` і httpOnly cookie. Для бойового сайту обов'язково задайте свій сильний пароль і `ADMIN_SESSION_SECRET` у змінних середовища сервера.

Якщо сайт буде працювати на serverless-хостингу, upload фото в локальну папку може бути тимчасовим. Для звичайного VPS це підходить. Для serverless краще підключити S3/R2-сховище для фото.

Після деплою перевірте:

- відкриття головної сторінки;
- вхід у `/admin`;
- збереження будинку і статусу планування;
- завантаження фото, PDF і відео;
- відправку заявки;
- події Meta Pixel і TikTok Pixel у кабінетах аналітики.
